## Integration contracts

- `parseVoiceCommand(text, targets)` returns a bounded command list, `[]` for intentionally ignored/ambiguous speech, or `null` for unresolved navigation eligible for Astra. It preserves negation, gives stop priority, supports ordered compounds and never chooses an arbitrary matching animal.
- `new VoiceController({context, onCommands, onStatus, onTranscript?, onActivity?})`. `context()` supplies `{sceneGeneration, sessionGeneration, targets:[{id,name}]}`. Only currently visible/eligible target instances belong here. `onCommands` receives the validated shared `CommandEnvelope`; the game simulation owns all application of motion. Do not store `onTranscript` output; the production UI does not use it. Optional `onActivity(activity, commandTypes?)` reports `hearing`, `interpreting`, `acted`, `ignored`, `narrating`, or `ready`; it carries command type names, never speech text. The prominent voice indicator uses these events.
- `start({adultDevelopment:true})` starts server-authorized adult local voice. The app derives this authorization from `status.adultDevelopmentMode` rather than an extra in-game checkbox. `start()` requests no microphone or network and returns `needs-setup`. `stop()` closes tracks, peer, channel, timers and in-flight requests; navigation stop remains a separate command and leaves listening enabled. `setTransmitting(false/true)` supports hold-to-talk after session setup. Releasing the hold disables the media track while permitting the in-flight utterance final to complete. `cancelPending()` must run for newer manual actions, scene changes and modal opening. `setNarrating(true/false)` coordinates echo suppression. `dispose()` also removes the visibility listener.
- `new AudioMixer()`: `unlock()` from a user gesture; `setHabitat('reef'|'caribbean'|'ice'|'wreck'|'deep')`; `setSurface(boolean)`; `setVolumes({ambience,narration,muted})`; `narrate(assetId)`; `cue('discovery'|'listening'|'swish'|'click', channel?)`; `stopNarration()`; `suspend()`; `dispose()`. Channels are ambience, movement, wildlife, UI, narration. Wire `mixer.onNarrating=v=>voice.setNarrating(v)`. Wire `onError` to a reassuring availability message.
- Narration IDs: `narration-${discovery.id}`, `destination-${habitat.id}`, `start-${habitat.id}-${spawn.id}`, `narration-activity-${activity.id}`, and `narration-welcome`, `narration-controls`, `narration-start`, `narration-surface`, `narration-return`, `narration-no-target`, `narration-idle`, `narration-listening`, `narration-stop`, `narration-help`, `narration-journal`.

`registerVoiceRoutes(app)` is mounted before static/Vite middleware. `/api/voice/status` exposes readiness/model names, no secrets. `POST /api/voice/enable` requires the exact allowed origin, an adult-mode request, a configured key and the server adult-mode opt-in. The application supplies the authorized mode when Start swimming begins play. It issues a scoped SameSite=Strict HttpOnly session cookie plus an in-memory CSRF token. `POST /api/voice/session` requires both, validates SDP size, and exchanges the offer server-side. `POST /api/voice/interpret` requires both and validates text/target count. `POST /api/voice/renew` requires the same active adult lease, exact origin and CSRF, rechecks server readiness, and extends the cookie/lease while resetting its per-lease quotas. Renewal is allowed only after eight minutes; expired or revoked leases cannot renew. `/api/voice/disable` revokes the application session.

## Actual provider contracts

Official documentation was fetched September 10, 2026. [Astra's model page](https://developers.openai.com/api/docs/models/gpt-6-astra) identifies text/image input and no audio. The server uses `gpt-6-astra` Responses with strict structured output, `store:false`, low reasoning effort, bounded output and no tools. It never produces wildlife facts or coordinates. Nullable structured-output fields are removed and the resulting discriminated command union is revalidated against target IDs.

[Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription) supports browser WebRTC and finalized `conversation.item.input_audio_transcription.completed` events. The shipped configuration uses **`gpt-4o-mini-transcribe`**, English (`language:"en"`), near-field noise reduction and server VAD (`threshold:0.5`, `prefix_padding_ms:300`, `silence_duration_ms:300`). [The WebRTC guide](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime) documents server-mediated multipart SDP/session exchange at `/v1/realtime/calls`. Actual September 10 provider testing rejected `gpt-live-transcribe` with server VAD (`400 invalid_value`, parameter `session.audio.input.turn_detection`: turn detection unsupported for that model); its unified handshake also returned 504. The compatible mini model established a real WebRTC session and the first synthetic WAV command moved Elise, with 959 ms from provider speech-stop event to final transcript and 962 ms to dispatch ([first-command evidence](../artifacts/voice/first-real-command-pass.json)). This is one synthetic case, not a full accuracy result. Audio never goes to Astra. Neither partial transcripts nor generated audio are command authorities.

Completed transcript item IDs are deduplicated; speech-start ordering rejects out-of-order older completions. New speech cancels unresolved interpretation. Envelopes carry utterance/command IDs, scene/session generations and finalization/creation times. Common-command stale rejection is two seconds after speech-end when known, otherwise after final transcript arrival. Astra fallback has an explicit 6.5-second envelope budget, while newer speech, manual input, narration, scene changes and stop still cancel it immediately; old responses never become fresh commands. Keyboard/touch stop cancels pending results immediately. Narration disables capture tracks, clears input and rejects pre-narration pending turns and potential echo turns. Echo cancellation alone is not treated as proof of feedback prevention.

Server SDP timeout is 35 seconds and the client deadline is 40 seconds; unresolved microphone permission times out after 15 seconds while late grants are stopped. Astra requests time out within 4.5 seconds, with a client cancellation deadline of 4.7 seconds. An initial actual diagnostic response took 3.2 seconds; the former 1.7-second cutoff discarded it. A subsequent three-attempt real probe recorded one 4.5-second timeout and two valid results at 3.578/3.360 seconds ([raw bounded results](../artifacts/voice/astra-real-probe.json)); fallback reliability is not inferred from the successful attempts alone. The UI reports interpretation while waiting, and common grammar commands do not incur this fallback delay. Connections can retry twice with 0.5/1-second backoff. The client automatically renews the explicitly authorized adult session at nine minutes, before the ten-minute server lease expires. It cancels old interpretations, closes the old channel/peer/tracks, renews the authenticated lease and establishes a fresh WebRTC connection. The indicator says reconnecting during the brief handoff; seamless audio during the handoff is not claimed. A failed or revoked renewal fails closed. Stop, settings, navigation away and hidden-page teardown cancel future renewals. Server session records expire after ten minutes without renewal, allow three handshakes and 100 protected requests per lease. Session creation is limited to 12 per IP per hour. `VOICE_FIXTURE_RUN=true` raises that limit to 45 only for an explicitly configured adult fixture run. These are application limits, not a provider spending guarantee.

## Configuration and child data gate

The no-key application is fully usable with local controls and narration. Following the user’s later instruction, initial page load runs `requestMicrophonePermission()` by default as a local-only permission preflight, unless the saved spoken-control preference is off. It closes granted tracks immediately, including late grants after its timeout or unmount, and creates no provider connection. This differs from starting a listening session. For authorized adult/synthetic development only:

```text
OPENAI_API_KEY=<server-only key>
ALLOW_ADULT_VOICE_DEV=true
APP_ORIGIN=http://localhost:5173
```

No key, token, transcript or recording is written to browser storage, application logs or production assets. Live tests use original synthetic WAVs, never recordings of children. The app does not claim speaker identification.

Child cloud enablement is deliberately hard-disabled server-side. An environment flag, parent checkbox, `store:false`, or lack of application logging cannot override this. [Under-18 guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance) and [data controls](https://developers.openai.com/api/docs/guides/your-data) require actual eligible account/project controls; no such deployment evidence is available. A future deployment review must record approval and selected project retention controls, current Realtime transcription and Responses endpoint/model compatibility, other age-appropriate safeguards and relevant deployment requirements before modifying that gate. Current documentation's endpoint eligibility is not proof this account is configured. **This build is not a child-ready cloud release.**

## Original local audio and rights

The shipped narration now contains 85 actual OpenAI `gpt-4o-mini-tts` / `marin` renditions of the reviewed scripts, normalized to mono 24 kHz PCM16. All files have matching fingerprints, checksums and measured loudness evidence; they play locally without a key. See [narration generation and audits](NARRATION.md). No real performer is recorded or cloned, and subjective warmth/pronunciation remains unverified by human listening. `npm run narration:build` regenerates changed lines with a configured key. `npx tsx scripts/audio-build.ts` remains an eSpeak fallback authoring route for missing/changed scripts and preserves matching preferred files; it is also the source of the original synthetic microphone fixtures.

[eSpeak NG](https://github.com/espeak-ng/espeak-ng) is GPL-3.0-or-later authoring software. [GPL section 2](https://espeak.sourceforge.net/license.html) distinguishes running the tool and the content of its output. Original project text is the synthesized content; neither the synthesizer binary nor code is distributed in the game. The registry documents the tool and output provenance instead of incorrectly claiming eSpeak itself is CC0. Original project output is approved for this project; this is not a grant of unrelated third-party rights.

Five underwater and five surface layers are deterministic original Fourier water/wind textures with periodic 12-second loops. They are artistic sound design, not field recordings or scientific claims about fish calls. Surface blends over 0.8 seconds; narration ducks ambience to 23% of its normal level. A compressor, conservative master gain, source cap of eight and buffer-cache cap of twenty bound output and resource use. Movement/UI swishes are explicitly designed feedback. The Australian surface soundscape includes a quiet, attributed CC0 buff-banded rail excerpt on the separate wildlife channel, verified against its original iNaturalist observation. It was recorded in Victoria, not at Green Island; see [bird recording provenance](BIRD_AUDIO.md). Other surface birds have no invented species calls. Human listening and comfort remain unverified.

Technical checks verify every hash, PCM structure, peak bound and loop boundary; Chromium decodes every shipped clip and exercises twenty-five habitat changes, narration, source/cache bounds and disposal. These checks do not prove the audio sounds warm or comfortable. Audible loop/transition review and real-speaker echo testing are **unverified**, since an auditory inspection tool and a physical adult microphone are unavailable in this session.

The last command exits with code 2 and a precise BLOCKED report when required configuration is absent. Set `LIVE_AUDIO_TEST=1` with a server key to explicitly authorize the synthetic provider run. It launches an isolated localhost server and Chromium fake-microphone capture using committed synthetic WAVs, normal app controls, and read-only simulation snapshots. It never substitutes injected text for live transcription. An independent real Astra request verifies a navigation paraphrase. Accuracy, stop success and quiet/negated outcomes are evaluated separately. The deterministic transcript suite is not evidence of speech recognition accuracy.

The live runner includes close and resume with actual discovery/pause preconditions (34 actual-audio cases); it excludes only the out-of-habitat jellyfish approach. It uses the normal spoken-controls preference to prevent automatic capture while preparing each fixture, then the normal microphone button to start real provider capture. This makes the audio path reproducible but does not certify default auto-start UX. Close gets a longer observation window to wait for local narration to finish and the looping synthetic utterance to reach the resumed microphone. A successful state match also requires matching allowlisted command types/arguments and a provider-derived dispatch timestamp, so the initial state or a different command with a similar effect cannot count as success. Quiet fixtures require a connected peer and zero dispatched commands. Read-only diagnostics retain only command metadata/counters and timing, not transcript text. The revised runner now has real provider access; the linked last-run report is authoritative about accuracy, latency, failures and whether it is a targeted subset or the full suite. Adult/synthetic results cannot establish five-year-old speech accuracy. A later supervised, consented human session should observe choosing a start, swimming, stopping, surfacing and opening a discovery, without recording a child by default. Physical microphone permissions/dismissal/unplug behavior, device speakers and live feedback need human/device checks even after Chromium fixtures pass.

## Voice-first continuous play verification

Voice is the primary play control when authorized setup is available; keyboard/touch remain immediate secondary controls. Common finalized phrases execute through the local bounded grammar in the same event turn, without an Astra network round trip: “go faster”, “go a little faster”, “go to the surface”, “what is this fish”, “close the card” and “resume playing”, among others. Astra handles only unresolved plausible navigation. Partial text never triggers movement; negation, ambiguous targets and unrelated speech remain no-ops. The discovery command asks the game to open its known selected subject, never to identify an animal from model speculation.

`tests/voice-continuous.test.ts` advances a real controller with fake capture/peer/network over twenty minutes, observes two renewals, executes commands afterward, verifies replaced tracks/channels/peers close exactly once, rejects late old-connection events, and proves stop cancels a pending renewal. It also verifies narration remains muted across renewal and fresh close/resume commands work after narration ends. `tests/voice-renewal-server.test.ts` exercises real local HTTP routes for twenty-minute authorization, expiry, early-renewal limits, origin/CSRF/revocation/readiness checks, and inspects a mocked provider request against the current low-latency schema. These are deterministic lifecycle/schema checks, not real recognition evidence. The latest passing count is recorded in `artifacts/voice-unit.json`.

Narration uses half-duplex playback: microphone transmission is disabled during Elise's narration, queued input is cleared, old turns are invalidated, and transmission resumes automatically afterward. The UI says Elise is speaking, then listening. Hands-free close/resume is available after narration; spoken interruption during playback is deliberately not promised. Physical loudspeaker echo, quiet children, accents and twenty-minute real-provider continuity still require authorized live testing. No transcript, provider key or audio recording is added to persistent storage by renewal or turn feedback.

## Direct startup after server configuration

For the already-authorized local adult mode, set `OPENAI_API_KEY` and `ALLOW_ADULT_VOICE_DEV=true` in the ignored server `.env`, restart the server, and reload the page. Allow microphone access, choose a destination/start and click **Start swimming**. There is no second adult-session checkbox. The client reads `adultDevelopmentMode` independently of credential readiness; `available` requires both that mode and a nonempty key. When the scene and microphone are ready, voice starts automatically. Menu narration is stopped and the welcome is a caption in voice-ready mode, so speech is not blocked by a welcome clip. The microphone button can retry a denied/failed capture and rechecks server readiness after configuration changes.

An empty or whitespace-only key produces a concrete `OPENAI_API_KEY is empty or missing` server status, an “OpenAI API key is missing” play indicator, and setup instructions. It never advertises listening or calls the provider in that state. Local permission alone is not evidence of a working cloud session. Child cloud readiness remains false; server-authorized adult mode does not override the child deployment gate.

`tests/voice-ui.spec.ts` now covers direct map → Start swimming → listening without visiting settings, plus the missing-key message and absence of the old checkbox. Its fake WebRTC events test UI/control integration only; they are not live speech recognition evidence. The coordinator runs browser verification serially with the other scene tests.

## Actual September 10 provider evidence

The complete [34-case real audio run](../artifacts/voice/full-real-suite.json) passed the specified ≥90% recognition/control gate at **32/34 (94.1%)**, with **all three stop cases and all seven no-action cases correct**. The two misses were the short synthetic words `resume` and `help`; both had connected peers and real finalized transcript events but dispatched no command. They remain failures in that report. Correct common commands had **438 ms median / 823 ms p95** from receipt of the provider speech-stop event to controller dispatch; transcription alone measured 436/822 ms. These timestamps do not independently measure acoustic end-of-speech or physical-device latency. Astra's independent actual Responses request returned validated lateral-right navigation in **2,428 ms**. The separate three-attempt probe above preserves its one timeout.

The run used original eSpeak-generated WAV command fixtures through Chromium's actual fake-microphone media track and real OpenAI WebRTC, on the developer network without artificial throttling. No injected transcript is counted as recognition. The full run used the final model and 4.5-second Astra server budget; afterward, a small controller-only feedback correction added return-to-listening and a visible retry hint on Astra timeout. That correction has deterministic timeout/cancellation coverage. Real adult microphones, accents, quiet children, loudspeaker echo and child usability remain unverified.

A [targeted actual-audio diagnostic](../artifacts/voice/short-word-diagnostic.json) repeated the two misses after the feedback correction. Each produced two nonempty provider final events, but neither matched its known synthetic fixture text, including after Unicode diacritic folding. This confirms recognition mismatch without retaining the recognized text; no permissive parser guesses were added. Both remain failed cases. The same diagnostic's real Astra request passed in 2,997 ms. [Frozen source hashes](../artifacts/voice/frozen-sources.json) identify the final reviewed implementation. `live-report.json` is the preserved complete 34-case report; targeted results have their own file.

## Historical latency experiments — not shipped

The later [ten-minute real soak](VOICE_SOAK.md) overrides any broad inference from the initial short suite: repeated stop audio produced 76 correct stops and six wrong vertical commands. It remains **FAIL**. The fixture has 2.215 seconds before its audible onset and 4.483 seconds after it; its 7.246-second loop has no obvious boundary overlap. No retained transcript can establish the exact earlier misrecognized words.

A [two-minute-per-model actual WebRTC diagnostic](../artifacts/voice/model-diagnostic.json) reproduced uncertain single-word movement on the same stop WAV. Mini produced 15 stops and two wrong vertical commands from 17 finals (408 ms median / 650 ms p95 recognition time). The larger `gpt-4o-transcribe` produced eight stops, four wrong movement commands and five ignored finals (431/697 ms). It was therefore not selected. Numeric token scores were retained without tokens or transcripts.

The [faster VAD diagnostic](../artifacts/voice/fast-vad-diagnostic.json) used mini with **150 ms silence detection and 600 ms prefix audio**. Its 17 finals produced 15 correct stops, one wrong vertical command and one ignored utterance, with 483/736 ms recognition time. Prefix audio preserves more onset context without deliberately waiting longer at the end. The configured endpoint wait is 150 ms shorter; the measured recognition component in this small sample was 75 ms higher, so this is **not** evidence of a 150 ms acoustic-end-to-action improvement. It also does not establish a stop-reliability fix. [Official VAD configuration](https://developers.openai.com/api/docs/guides/realtime-vad) describes the separate prefix/silence controls and the turn-splitting tradeoff.

An experimental candidate requested `item.input_audio_transcription.logprobs` and declined **isolated single-word non-stop commands** whose minimum lexical token score is below 0.8, showing “I missed that. Please say the command again.” Complete phrases followed ordinary parsing, avoiding rejection solely because a function word is uncertain. Stop remained immediate even at low confidence. Missing optional score metadata preserved protocol compatibility; malformed supplied metadata was rejected. That heuristic added no request or waiting interval and was not a calibrated probability of correctness. One observed wrong word scored 0.896 and would pass the guard, so the limitation remains explicit. A declined utterance is not counted as a correctly recognized stop.

The largest intended responsiveness change is [local routing of clear everyday phrases](VOICE_LATENCY.md), which avoids Astra entirely for requests such as “I want to swim forward” and “can we go to the surface.” Those phrases previously incurred the separate interpretation hop. The user clarified that the requested speed increase concerns Elise’s physical swimming speed. VAD tuning and the confidence guard were therefore reverted before release; no full-suite result is claimed for those candidates. The validated natural-phrase parsing improvements remain. The production configuration is `gpt-4o-mini-transcribe`, 300 ms prefix / 300 ms silence, without requested logprobs or confidence gating. Original soak recognition failures remain unresolved and preserved.
