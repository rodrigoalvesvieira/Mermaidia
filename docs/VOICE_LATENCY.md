# Voice response improvements

The user initially described slow spoken navigation, then clarified that the character’s physical swimming speed was the issue. The final game increases swimming speed; experimental provider/VAD/confidence changes were reverted to the previously verified voice configuration. Clear everyday requests now resolve directly in the local command parser after OpenAI transcription, including “I want to swim forward”, “can we go to the surface”, “can we go faster”, “take me up”, and “go straight ahead”. They do not need a second interpretation request. Negative and conflicting requests retain their no-movement behavior. Movement still waits for a finalized transcript so an incomplete phrase cannot start an unintended action.

The [deterministic before/after comparison](../artifacts/voice/latency-parser-comparison.json) uses the previous staged parser and the current parser. It shows that the forward and surface requests previously required interpretation, the polite faster request was previously ignored, and the negated forward request remains ignored. This comparison establishes routing, not wall-clock speech latency.

The [browser protocol check](../tests/voice-ui.spec.ts) now uses natural forward, faster and surface requests and asserts zero interpretation requests. Both Chromium cases passed in 31.2 seconds: [actual log](../artifacts/e2e-latency.log). This is integration evidence using simulated transcripts, not recognition evidence. Twenty-six additional grammar cases cover natural requests and negations.

Four separately generated [actual-audio fixtures](VOICE_LATENCY_FIXTURES.md) cover polite speed, forward, surface and a negation without altering the original 35-fixture corpus. These four extension clips have not been sent through the live provider; no recognition or wall-clock speedup is claimed for them. The original real-audio fixture report remains separate evidence. The model/VAD diagnostic experiments are documented in [voice setup](VOICE.md); none of their configuration changes shipped. The final configuration remains mini transcription with 300 ms silence and 300 ms prefix padding. See [swimming changes](IMPLEMENTATION_STATUS.md) for the actual requested speed increase.
